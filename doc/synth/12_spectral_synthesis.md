# 12. スペクトル合成 (Phase 5)

岡山に建設中の **R = 300,000** の分光器で観測されるスペクトルを、
R2D2 の 3D 計算から後処理で合成する。

方針は「**gray で流体を解き、後処理で高分解能スペクトルを出す**」。
多群化 (Phase 3-4) を待たずに始められ、線の形は後処理側の解像度で決まる。

```
R2D2 3D (T, P, rho, v_x)
   → 柱ごとに視線に沿って形式解        odfgen/synth.py: synth_column
   → 水平平均 → 装置プロファイルで畳む  instrument_profile
   → バイセクタ・線位置                bisector, line_centre
```

不透明度は (T,P) 格子上に R = 10^6 で事前計算しておく
(`scripts/build_opacity_table.py`)。**vturb = 0 で作ること** —
3D の速度場が乱流を含んでいるので、1D 用の微視的乱流を足すと二重計上になる。

## 1.5 形式解のスキーム: 対数を取ってから線形近似する

**Hotta & Iijima (2020) / Hotta & Toriumi (2020) Appendix A** の方式に合わせた
(既定 `scheme="log"`)。光球では H^- のせいで kappa が 1 セルの間に桁で変わるので、
セル内で alpha と S をどう変化させると仮定するかが効く。

### 何を仮定するか

`ln(alpha)` が経路長について線形 (= alpha は指数関数的に変化) とすると、
光学的厚みに使う代表値は **対数平均**になる:

    <alpha> = (a1 - a0) / ln(a1 / a0)

**幾何平均ではないことに注意。** alpha が 1 セルで 1 -> 100 と変わる場合:

| | 値 | 意味 |
|---|---|---|
| 算術平均 | 50.5 | alpha が線形に変化すると仮定 (従来) |
| 幾何平均 | 10.0 | log 空間の**中点の値**。区間平均ではない (過小評価) |
| **対数平均** | **21.5** | ln(alpha) が線形なときの**厳密な区間平均** |

一般に 幾何平均 <= 対数平均 <= 算術平均。指数関数的変化を数値積分しても 21.50 で、
対数平均と一致する (`tests/test_physics.py`)。

source function も同様に `ln(S)` が tau について線形とすると、寄与は解析的に

    int_0^dt S exp(-(dt - t')) dt' = (S_d - S_u exp(-dt)) / (1 + ln(S_d/S_u)/dt)

と積分できる (u = 上流 = 深い側, d = 下流 = 浅い側)。
S を tau について線形補間すると急勾配のところで**負になり得る**のに対し、
log なら常に正で、桁で変わる状況に強い。

### S も log にする

`ln(S)` が **tau について**線形 (HI20 eq. C8)。R2D2 本体と同じ流儀である。

**HI20 (Hotta & Iijima 2020, MNRAS 494, 2523) Appendix C との対応**
(`papers/` に PDF あり)。式は完全に一致している:

| HI20 | 内容 | 我々の実装 |
|---|---|---|
| (C2) | セル境界値は対数値の線形補間 (= 幾何平均) | 柱は格子点上なので不要 (mu=1) |
| (C4) | **ln alpha(z) が z について線形** | `scheme="log"` の前提 |
| (C5) | Delta tau = (a1-a0)(z1-z0)/(ln a1 - ln a0) / mu = **対数平均** | `_log_mean` |
| (C8) | **ln S(Delta tau') が Delta tau' について線形** | `r = log(s_d/s_u)` |
| (C9) | I = I_up e^-dt + dt (S_d - S_u e^-dt)/(ln S_d - ln S_u + dt) | `integ = d*(s_d - s_u*ex)/(d + r)` |

HI20 は「先行研究では放物線や 2 次 Bezier (Auer 2003) が使われるが、
**我々は対数値の線形関数を採る**」と、意識的にこの選択をしている。

なお (C5) は a0 = a1 に特異点があり、HI20 は Taylor 展開で回避している。
我々は `|ln(a1/a0)| < 1e-8` で算術平均に落としている。算術平均は
対数平均の O(x^2) 近似 (誤差 a0 x^2/12) なので、この閾値では相対誤差 1e-16
で実害は無い。

**Phase 4 (R2D2 本体の多群化) で効く点**: HI20 は輻射加熱 Q を光学的に
薄い側では平均強度から (C10)、厚い側では流束の発散から (C12) 評価し、
tau0 = 0.1 で滑らかに切り替えている (C14)。多群化ではこれを群ごとに
やることになる。

理想化した大気 (上端が薄く冷たく、深いほど alpha も S も大きい) での収束:

| 点数 | 格子 | linear の誤差 | **log の誤差** |
|---|---|---|---|
| 5 | 0.25 | -10.36% | **-7.66%** |
| 9 | 0.125 | -2.91% | **-2.02%** |
| 17 | 0.0625 | -0.75% | **-0.52%** |
| 33 | 0.031 | -0.19% | **-0.13%** |

alpha が 1e4 倍・S が 100 倍変わるより急な場合でも同じ傾向 (5 点で
-21.3% vs -17.3%)。**誤差は 25-30% 減るが、桁では効かない。**

### どれくらい効くか (実測)

`scripts/test_formal_solution.py`。8 倍細分 (3 km) の解を基準に、
格子を間引いたときの残留強度の誤差:

| 格子 | linear | **log** | 改善 |
|---|---|---|---|
| 24 km (d001 の実解像度) | +0.0199 | **+0.0153** | 23% |
| 48 km | +0.0345 | **+0.0283** | 18% |
| 96 km | +0.0744 | **+0.0612** | 18% |
| 192 km | +0.1620 | **+0.1315** | 19% |

細分格子では両スキームが一致する (0.2340 / 0.2341) ので実装は正しい。
基準解は大気の補間法 (log / linear) にも依らない。

**log の方が常に良いが、誤差を消すわけではない。** 残る誤差の主因は形式解では
なく**大気そのものの鉛直サンプリング**である。

### 重要な帰結: 以前の「観測と 3% 一致」は数値誤差込みだった

24 km の格子では、形式解の誤差だけで残留強度が 0.015 浅く出ていた。
収束解で測り直すと:

| | 24 km での値 | **収束値** | 観測 |
|---|---|---|---|
| 残留強度 | 0.254 | **0.234** | 0.342 |
| 等価幅 | 118.9 mA | **123.5 mA** | 113.0 mA |

つまり**数値誤差が物理的な食い違いを一部打ち消していた**。等価幅の一致は
3% ではなく **9% 過大**が正しく、線の深さの食い違いも見かけより大きい。

なお **R2D2 本体の RTE は元から log スキーム**である (HI20)。
素朴な linear を使っていたのは我々の後処理側だけだった。

### 群分けの tau も同じ流儀に直した

`odfgen/binning.py: tau_unity_depth` は、各 (bin, sub) で tau_lambda = 1 に
なる場所の tau_Ross を求めて群を割り当てる、**Phase 3 の中核**である。
ここが `np.gradient` を使った中点則で、alpha を点の値で評価していた。
これは指数関数的に変化する alpha に対して実質**幾何平均**を使うのと同じで、
系統的に過小評価する。対数平均に直した。

影響は小さかった: 4 群の要素数が
[245, 203, 654, 758] → **[245, 204, 669, 742]** で、1860 要素中 16 個
(0.9%) が群 3 と 4 の間を移動しただけ。群不透明度は 4 桁目しか変わらない。
群境界が log tau のしきい値なので、数 % の tau のずれではまたがりにくい。

### 副産物: 壊れた入力が炙り出された

log スキームは alpha <= 0 で NaN になるため、`k-omega` フィルタが上層で
**負の圧力・密度を作っていた** (756 / 3.3e6 点) ことが判明した。
linear スキームはこれを黙って飲み込んでいて気付けなかった。
フィルタ側を「正値の量は log を取ってからフィルタし exp で戻す」ように直し、
`formal_solution` は負の入力で明示的に落とすようにした。

## 2. 線位置を測るときの落とし穴 (3 つとも実際に踏んだ)

### 2.1 重力赤方偏移 (636 m/s) — 輻射輸送には入っていない

光子が太陽の重力ポテンシャルを登る分の赤方偏移

    GM_sun / (R_sun c) = 636 m/s

は形式解の式のどこにも現れない。観測と比べる前に**合成側の波長を伸ばす**。
これを忘れると 636 m/s まるごと系統誤差になる
(`compare_solar_atlas.py --grav-redshift`、既定で有効)。

### 2.2 p モード (音波) — 水平平均では消えない

箱全体が同位相で上下する p モードは、水平平均しても残る。
実測で光球付近の水平平均 `<vx>` は rms 170-240 m/s、振れ幅 +-600 m/s。
**スナップショット 1 枚から作った線位置は、これだけの偶然のずれを持つ。**

対策は 2 つあり、後者の方が良い:

1. 時間平均する (相関時間 1.5 分に対し 3 分間隔で 20 枚)
2. **k-omega フィルタ**で音波成分だけ落とす (`scripts/kw_filter.py`)。
   水平 2 次元 + 時間で Fourier 変換し、位相速度 omega/k_h が音速を超える
   成分を除いて逆変換する。対流は omega/k_h ~ v_conv << c_s なので残る。
   k_h = 0 で omega != 0 の成分 (= 箱全体のピストン運動) が全部落ちるのが効く。

**効果の実測** (d001, Fe I 6301.5, 5 枚の独立なスナップショット):

| | 平均 | 1 枚ごとのばらつき |
|---|---|---|
| 生データ | +537 m/s | **216 m/s** |
| k-omega フィルタ済み | +404 m/s | **50 m/s** |

**ばらつきが 4 分の 1 になる。** つまりフィルタをかければ
スナップショット 1 枚でも線位置が +-50 m/s で決まる。
20 枚平均しなくてよいので、時間変動の解析ができる。

なお、フィルタをかけると線コアがわずかに深くなる (0.248 → 0.222)。
p モードによる広がりが消えるためで、これ自体は正しい。
ただし我々の線は元々深すぎるので、**見かけ上は悪化する** — 
広がり不足という本質的な問題を p モードが偶然埋めていただけである。

### 2.3 線中心を「格子上の最小値」で取ってはいけない

合成格子は R = 10^6 なので **1 点 = 299 m/s**。
`argmin` で線中心を取ると、測定値が 299 m/s 刻みに量子化される。
見たい対流ブルーシフトは数百 m/s なので、これでは分解できない。

実際、この方法では 5 枚のスナップショットの線位置が
+18 / +318 / +618 m/s と綺麗に 3 通りの値しか取らず、
一時「20 枚平均で +18 m/s まで合った」と誤って結論した。
コア付近に**放物線を当てて頂点を取る**ように直した
(`compare_solar_atlas.py: line_centre`)。正しく測ると +330 m/s である。

## 2.5 **上部境界が線コアに効いている** (2026-08-16 発見)

`scripts/contribution_function.py` で、出射強度の被積分関数

    CF(z) = S(z) exp(-tau(z)) alpha(z)

を高さの関数として測った (d002, n=78)。

| | 線コア | 連続光 |
|---|---|---|
| 寄与の中央値の高さ | **+394 km** | +34 km |
| 90% が来る高さまで | +298 km | -38 km |
| **上端から 300 km 以内の寄与** | **48.1 %** | 0.1 % |
| 上端から 150 km 以内 | 7.5 % | 0.0 % |

R2D2 の箱の上端は `xmax = rstar + 700.d5` = **+700 km**。
線コアの形成高度 (+394 km) との差は 300 km で、上層の圧力スケールハイト
(120-150 km) の 2 個ぶんしかない。**線コアの強度の約半分が、
上部境界の影響が及ぶ範囲で作られている。**

連続光は +34 km 形成でほぼ無関係なので、**規格化した線の深さだけが
境界の影響を受ける**。これは我々が見ている症状 (連続光は合うのに
線が深すぎる) と完全に一致する。

比較: **Witzke et al. (2024) の MURaM は上端 +1000 km** で、
「温度極小まで覆う (which covers the photosphere up to the temperature
minimum)」と明記している。同じ形成高度に対して 600 km の余裕がある。

**対策**: 上端を +1000 km へ伸ばす。12 km 格子なら 25 点追加 = 格子数 +5%
なので計算コストはほぼ変わらない。ただし注意が 2 つ:

1. HI20 Appendix A によれば、Model S の上端は光球の約 500 km 上で、
   そこから上は `g(z) ∝ (z+R)^-2`・**等温**で外挿している。
   +1000 km にすると 500 km ぶんが外挿領域に入る。
2. 低密度層を足すと音速・Alfven 速度が上がって dt が落ちる可能性がある。

**この境界の問題は d001 と d002 で共通**なので、両者の差 (線位置の改善) は
説明しないが、**両方が深すぎることは説明しうる**。

## 3. 現状の結論と次の一手

正しく測ると、合成線は観測より **+330 - +400 m/s 赤い**。
すなわち**対流ブルーシフトが 300-400 m/s 足りない**。
バイセクタ平均速度でも同じ向きの差が出る (合成 +764 / 観測 +344 m/s)。

対流ブルーシフトは「明るく上昇する粒状斑が青方偏移して重み大きく効く」
という強度と速度の相関で決まるので、**粒状斑内部の速度勾配が解像されて
いないと小さく出る**。d001 は tau=1 で 1 スケールハイトあたり 5.9 点しか
なく、標準的な光球計算 (10-16 km, 10-14 点/H_p) の半分である。

→ **d002 (512 x 256 x 256, 鉛直 12 km) で同じ測定をやり直すのが次の一手**。
線幅 (12% 不足)・コアの深さ (0.26 vs 0.34)・ブルーシフト (350 m/s 不足) が
同時に改善するはずで、しなければ原因は解像度ではない。

残る系統誤差の候補 (解像度で説明できなかった場合):

1. **gray であること**。光球上層の温度が多群より高く出るので、
   強い線のコアは系統的にずれる。→ Phase 3-4 の多群化で改善するはず。
2. **LTE**。Fe I 6301.5 は NLTE 効果が小さい線として選んでいるが皆無ではない。
3. **mu = 1 の鉛直光線のみ**。disc centre の比較なので影響は小さい。
4. 線データ (log gf, van der Waals 定数) の不確かさ。

# 4.5 **重大な訂正: 比べる相手を間違えていた** (2026-08-17 夜)

**プロジェクト開始以来ずっと、mu=1 の合成を「全面平均 (disk-averaged) の
アトラス」と比べていた。** 正しくは視線中心 (disk-center) と比べなければ
ならない。5 章より前の「観測」の数値は**全てこの誤りを含む**。

### どういう間違いか

Neckel (1987) の Hamburg FTS アトラスは 20 ファイルあり、**2 系統に分かれる**。
同梱の解説 `Neckel-1987-notes-Trieste.pdf` の 1 ページ目にこう書いてある:

> "The atlas data are arranged in 20 files: files 1 - 10 contain the
> data-triplets ... for the **disk-averaged** spectrum, files 11 - 20 those
> for the **disk-center** spectrum."

`scripts/compare_solar_atlas.py` の `ATLAS_FILES` は file01-file07、つまり
**全面平均**を指していた。我々の合成は箱の上端から出る mu=1 の強度なので、
比べるべきは file11-file17 である。

**割り当てが正しいことの独立な確認** (解説を信用しない場合):

| 検証 | 結果 |
|---|---|
| 連続光の比 file14 / file04 | **1.207**。6300 A の周縁減光 I(mu=1)/<I> ~ 1.2 と一致 |
| Fe I 6301.5 の線幅 | file04 の方が広い。全面平均は自転 (~1.9 km/s) で広がる |
| Fe I 6301.5 の残留強度 | 全面平均 **0.342** / 視線中心 **0.273** |

### もう 1 つの間違い: 空気->真空の戻し方

アトラスの波長は Neckel 自身の式

    lam_air = 0.99972683 * lam_vac + 0.0107 - 196.25 / lam_vac

で真空から空気に落とされている。我々はこれを**汎用の式 (Edlen / Piskunov)**
で戻していたので、**6300 A で +23 m/s、4000 A で -24 m/s** の系統誤差が
入っていた。**作った人が使った式をそのまま逆に解く** (`neckel_air_to_vacuum`)。

### どれだけ変わったか (R2D2 d001, 同じスナップショット)

| | 誤: 全面平均 + 汎用の式 | 正: 視線中心 + Neckel の式 |
|---|---|---|
| 観測の残留強度 | 0.342 | **0.273** |
| 観測の等価幅 | 113.0 mA | **115.4 mA** |
| 観測のバイセクタ平均速度 | +344 m/s | **+242 m/s** |

**「線が深すぎる」問題は、思っていたより小さかった。** 5.4 節の
「温度を上げると深さと等価幅を同時に満たせない」という結論も、
正しい観測値では大きく緩む (下記 5.4 の訂正)。

# 5. Stagger との比較で分かったこと (2026-08-17)

> **注意**: この章の「観測」の数値は上記 4.5 節の訂正前のもの
> (全面平均アトラス) である。**結論の向きが変わる箇所があるので、
> 各節の訂正注記を必ず読むこと。** モデル同士の比較 (R2D2 対 Stagger の
> T(P) 差など) はアトラスを使っていないので影響を受けない。

## 5.1 まず、致命的なバグが 1 つあった

|---|---|---|
| d001 (15 枚) | +420 +- 56 m/s | **-19 +- 55 m/s** |
| d002 (11 枚) | +552 +- 78 m/s | **-60 +- 55 m/s** |
| Stagger (10 枚) | — | **+11 m/s** |

**+67 m/s**、つまり対流ブルーシフトがほぼゼロだった。3D 計算でこれは
起こり得ないので、合成側を疑うことになった。

我々のアトラス読み取りは 6301.5115 A で、**24 m/s で一致**する。

### 5.5.1 上端の位置と境界条件は除外できていない

上の表で「無関係」としたのは、**+674 - +871 km の層が線に直接寄与する分**
(残留強度で 0.003) だけである。**上端をどこに置き、そこで何を課すかが
力学的・熱的に下の領域を変える可能性は、全く除外できていない。**

R2D2 の上端 (`bcx.F90`) は **剛体の蓋**である:

* `vx = 0` (反対称) — 音波と対流のオーバーシュートを反射して閉じ込める
* `by = bz = 0` (反対称) — 磁場を鉛直に強制
* **`s1` が対称 = エントロピー勾配ゼロ** — 上端に熱的条件を直接強制しており、
  これが下方へ効く経路がある
* 減衰層 (sponge) は無い (`cdmp` は下端の圧力にしか使われていない)

対する **Stagger は上端 +871 km で鉛直境界が開いている** (Beeck et al. 2012
および Magic et al. 2014: "The horizontal boundaries are periodic and the
vertical ones are open")。**この差自体が 240-290 K の温度差の候補である。**

鉛直速度の rms を高さで見ると、R2D2 は +598 km の 1.29 km/s から
上端 +694 km で 0.43 km/s へ落ちる。蓋の影響が下方に及んでいる範囲は
上層のスケールハイト (120-150 km) の 1-2 個ぶん、すなわち +400-550 km まで。
線コアの形成高度 (+394 km) はその縁にある。

**測定中**: d004 (24 km, 上端 +1000 km, sign 境界) と
d005 (24 km, 上端 +700 km, sign 境界) を同条件で走らせ、
**上部光球の T(P) が変わるか**を見る。d001 (24 km, +700 km, 剛体の蓋) と
合わせて 2x2 になる。

## 6. mu を振った合成と円盤積分の設計 (2026-08-17)

RV の最優先項目 (タスク #17)。**まだ実装していない。ここは設計の記録**。

観測は円盤全面を積分した光を見るので、rest frame の視線速度は
`v_los = mu * v_x + sqrt(1-mu^2) * (v_y cos phi + v_z sin phi)`
(x は鉛直、mu = cos theta)。**mu = 1 の柱だけを合成しても円盤積分にはならない。**
円盤の面積の半分は mu < 0.71 にあり、そこでは水平速度が視線に乗る。

### 6.1 反復は要るか — 要らない (ただし理由を理解しておくこと)

**結論: 我々の後処理合成では反復は不要。** 光線を**箱の下端から上端まで
一本の長特性 (long characteristic) として通し切り、水平の周期性は
「強度を側面から入れ直す」のではなく「座標を fmod で巻く」ことで扱う**限り、
初期条件が無い面は現れない。下端 (拡散近似) が唯一の入射条件で、
そこから 1 パスで解ける。

**一方 R2D2 本体の RTE は反復している** (`R2D2plus/src/all/rte_multiray.F90`)。
理由は我々と条件が違うからで、混同しないこと:

| | R2D2 本体の RTE | 我々の後処理合成 |
|---|---|---|
| 欲しいもの | 全セルの J (加熱 Q = 4pi(J-S)) | 上端から出る I だけ |
| 必要な方向 | 全方向 (mrad x 8 象限) | 1 方向ずつ |
| 分割 | MPI で x,y,z を分割 | 1 プロセスに箱ごと載る |
| 解き方 | 短特性 + 面から流入 | 長特性を通し切る |
| 側面の流入 | **未知** (周期性で自分に戻る) | 巻いて同じ光線を続ける |
| 反復 | **要る** | 要らない |

R2D2 の反復の実装 (読むと勉強になる):

* 側面の流入強度を**推測**して 1 スイープする。
  最初の 2 ステップ (`ns <= 2*mhd_rte_ratio`) は `1.d-10`、
  それ以降は**前 2 回の RTE の値から時間線形外挿** (`tmp = dt_rte(2)/dt_rte(1)`)。
* MPI で隣と境界強度を交換し、**受け取った値と自分の値の最大相対差**
  `in_diff` を取る。
* 全ランクで `mpi_allreduce(max)` し、`in_diffg >= epc` なら
  `goto 1234` でスイープをやり直す (`epc = 1.d-4`, `rte_def.F90`)。
* 収束したら境界値を次回の初期推測として保存する
  (だから定常に近いほど反復回数が減る)。

**反復が必要になる条件を一般化すると**「解こうとする面の流入強度が、
その面より下流の未計算値に (周期性や領域分割を通じて) 依存するとき」。
我々の合成でこれを踏むのは次の場合なので、避けること:

1. 合成を**高さ方向に分割**して並列化する → 踏む。
   **波長と柱で並列化すれば踏まない** (こちらを採る)。
2. 光線を側面で打ち切って周期境界から入れ直す → 踏む。**巻いて続ける**。
3. **散乱を入れる** (S が J に依存) → Lambda 反復が必要。
   現状は散乱を吸収として扱っているので該当しない。

### 6.2 傾いた光線の刻み幅

鉛直 1 格子進む間に水平へずれる格子数は `(dz/dh) * sqrt(1-mu^2)/mu`。
R2D2 と同じ格子 (dz ~ dh) だと **mu <~ 0.7 で 1 を超える**、つまり
鉛直格子と同じ刻みでは**構造を飛び越す**。刻みは R2D2 の RTE と同じ
`ds = min(dx/mu_x, dy/mu_y, dz/mu_z)` で決める。
鉛直 50 層の箱で必要な光線上の点数の実測: mu=0.9 で 50、mu=0.5 で 86、
mu=0.3 で 158、**mu=0.1 で 495**。

### 6.3 補間

* **正値の量 (T, P, rho, alpha, S) は log 空間**、**速度は線形**。
  HI20 eq. (A2) が 8 近傍を log で補間しているのと同じ流儀。
  形式解の dtau が「alpha が経路長に対して指数関数」を仮定している以上、
  端点の値も log で補間しないと一貫しない。
* 水平は双線形 + 周期の巻き。鉛直は格子上に乗るので不要。

### 6.4 箱の幅という制約 (これが効く)

厚さ 1.194 Mm の合成層を通る間の水平移動距離 = `1.194 * sqrt(1-mu^2)/mu` Mm:

| mu | 水平移動 [Mm] | d001 (6.1 Mm) の周回数 | ml_deep (55.3 Mm) |
|---|---|---|---|
| 0.5 | 2.07 | 0.34 | 0.04 |
| 0.3 | 3.80 | 0.62 | 0.07 |
| 0.2 | 5.85 | 0.95 | 0.11 |
| 0.1 | 11.88 | **1.93** | 0.21 |

**6.1 Mm の箱では mu <= 0.2 で光線が箱を 1 周以上する**。同じ粒状斑を
2 回通るので、その mu の結果は信用できない。**低 mu は広い箱 (ml_deep,
55.3 Mm) とセットでしか意味がない。**

### 6.5 実装と検証の順序

1. 傾いた柱を通す関数を書き、**mu=1 で既存の `synth_column` と一致すること**
   を確認する (回帰テスト)。
2. d001 (6.1 Mm) で **mu >= 0.3 だけ**試す。
3. **周回の影響を実測する**: 同じ mu で箱を人為的に半分に切り、
   結果が変わるかを見る。変われば箱幅が足りない。
4. 本番は ml_deep の広箱で全 mu。方位角 phi は 4 点 x mu 8 点 = 32 方向。
   1024 柱 x 100 スナップショットで 60 コア x 83 分 (見積り)。

### 6.6 参考: 学生さんの C++ 実装 (`add_20260716.hpp`) を読んだ所見

長特性 + 周期巻き + HI20 の log スキームという**方針は我々の設計と同じ**。
`dtu = alpha_u * ds / (ln(1+a)/a)` (a = alpha_d/alpha_u - 1) は
対数平均 `(a1-a0)/ln(a1/a0)` と厳密に等価で、
source 項も `dtu*(S_d - S_u exp(-dtu))/(ln S_d - ln S_u + dtu)` と一致する。
**独立な実装が一致したので、`odfgen/synth.py` の形式解は裏が取れた。**
`intensity` (x 主走査) と `intensity_1` (y 主走査) を使い分けているのも
6.2 節の `min(dx/mu_x, dy/mu_y)` と同じ考え方。

気付いた点 (自分たちが実装するときも同じ罠を踏む):

* `log_al_v`, `log_so_v` を渡して補間までしているが、**結果を使っていない**
  (実際に使うのは線形補間した `al_v`, `so_v`)。log スキームの一貫性から
  言えば端点も log 補間すべきで、かつ今はメモリ帯域の半分が無駄。
* `#pragma omp for` が `parallel` 領域の外にあるので**並列化されていない**。
  さらに `iu, ju, dtu, ...` がループ外の宣言なので、`parallel for` にした
  瞬間に共有変数の競合になる (宣言をループ内に移すのが安全)。
* `fmod` 後の `ju_i + 1` が `jx` に達しうる (**添字の範囲外**)。
  巻きは `(ju_i+1) % jx` にするか、margin を持つこと。
  `dely` が負の場合 `fmod` は負を返すので、正の剰余に直す必要もある。
* `tau=1` 面の位置 `x_tau` は、`dtu_sum[ii]` が「光線点 ii-1 から上端まで」
  である一方 `tau_u` を光線点の番号として使っているので、**添字が 1-2 点ずれる**
  可能性が高い。ここは単体テスト (一様 alpha で解析解と比較) を書くべき。
* `intensity` は `py::tuple` を返す宣言なのに **return 文が無い**
  (コメントアウトされたまま) ので未定義動作。
